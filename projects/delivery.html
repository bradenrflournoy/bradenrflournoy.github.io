Package Delivery Database

MySQL SQL

Open the full EERD (PDF) →

A relational database for a package-delivery company — from a conceptual Enhanced ER design through a normalized MySQL schema and a full layer of transactional stored procedures and views.

This was a three-phase database systems project (CS 4400) modeling the operations of a delivery business: warehouses, trucks, drivers, multi-leg routes, customer orders, and the packages that flow through them. The core challenge was capturing a real role hierarchy — a single person can be a customer, an employee, and then a specialized driver or warehouse worker — cleanly enough that it maps to a sound relational schema.

Phase 1 — Enhanced ER design. I helped model the domain as an EERD (shown above), including the user role hierarchy, the relationships that connect trucks to routes and routes to their ordered sequence of legs, and how packages are boxed, stored, and carried. It captures entities like User, Employee, Contractor, Customer, Warehouse, Warehouse Worker, Driver, Truck, Route, Leg, Order, and Package.

Phase 2 — Relational schema. The EERD was mapped to a normalized MySQL schema with the role hierarchy resolved into dedicated tables (user, employee, contractor, customer, driver, warehouse_worker, packer) plus the operational tables (warehouse, truck, route, leg, order, package) and the relationships between them, with keys and constraints enforcing integrity.

Phase 3 — Stored procedures and views. On top of the schema I implemented the application logic as transactional stored procedures — hiring and firing drivers, registering packers, adding trucks and reassigning them, starting/extending/deleting routes, adding and routing packages, and more — using serializable isolation so concurrent operations stay consistent, along with views over the data.

It’s a compact end-to-end example of turning a messy real-world domain into a correct, normalized, transaction-safe database.
